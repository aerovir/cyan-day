# 🥂 «Синий день календаря»

«Синий день календаря» каждый день заглядывает в календарь и находит там праздники, о которых человечество почему-то предпочитало молчать. День космонавтики, День объятий с кактусом или Международный день ирландского кофе — любой повод становится достойной причиной ненадолго забыть о здравом смысле. Каждый праздник превращается в ироничную историю о жизни, работе, внезапной мудрости и других последствиях слишком серьёзного отношения к реальности. Ведь если уж день официально признан праздничным, значит, его необходимо отметить — желательно с юмором, лёгким похмельем и верой в светлое будущее.

Бот ежедневно публикует в VK-группе посты про праздники на сегодняшнюю дату. Описания превращаются в ироничные истории с сарказмом, юмором и тематическими картинками.


## Как это работает

```
SQLite SourceRegistry (включённые кодо-определённые адаптеры)
        │  SourceItem: название, описание, картинка
        ▼
Дедупликация событий → ИИ Mistral (иронично-алкогольный стиль)
        │
        ▼
VK API (публикует посты)

При пустом/отсутствующем реестре режим auto сохраняет fallback на calend.ru.

calend.ru (праздники на сегодня)
        │  (legacy fallback)
        ▼
ИИ Mistral (переписывает описание в иронично-алкогольном стиле)
        │  (пост)
        ▼
VK API (публикует пост с картинкой в группу)
```

## Архитектура

| Модуль | Назначение |
|---|---|
| `app/holidays_parser.py` | Сбор праздников с calend.ru |
| `app/ai_generator.py` | Генерация ироничных алкогольных постов через Mistral |
| `app/vk_publisher.py` | Публикация постов в VK-группу |
| `app/main.py` | Оркестратор: собрать → сгенерировать → опубликовать |
| `app/content_store.py` | SQLite: карточки, claims/provenance, план и ledger публикаций |
| `app/content_planner.py` | Детерминированный выбор карточек по семи слотам |
| `app/content_admin.py` | CLI для импорта и планирования контента |
| `main.py` | Точка входа (обёртка) |
| `scheduler.py` | Планировщик ежедневного запуска (замена cron) |
| `tests/` | Тесты (pytest) |

## Запуск

### 1. Получить ключи

#### VK (токен группы)
1. Создай сообщество (группу) VK.
2. Зайди в **Управление → Настройки → Работа с API**.
3. Создай **токен сообщества** с правами: `wall`, `groups`, `photos`.
4. Скопируй токен — пригодится как `VK_TOKEN`.
5. ID группы (число) — как `VK_GROUP_ID`.

#### Mistral (API-ключ)
1. Зарегистрируйся на [console.mistral.ai](https://console.mistral.ai).
2. В **Billing** выбери бесплатный план **Experiment** (без карты).
3. В **API Keys** создай ключ → скопируй сразу (показывается один раз).
4. Это будет `MISTRAL_API_KEY`.

### 2. Настроить `.env`

Скопируй пример и заполни (ключ Mistral нужен в `.env`, т.к. деплоя из GitHub нет):

```bash
cp .env.example .env
# отредактируй: VK_TOKEN, VK_GROUP_ID, MISTRAL_API_KEY
```

Открой `.env` и впиши значение в `MISTRAL_API_KEY=` (ключ ты создал на
console.mistral.ai). Тот же ключ — в `VK_TOKEN` и `VK_GROUP_ID`.

> **Важно:** `.env` в `.gitignore` — ключ не попадёт в репозиторий.

### 3. Запуск через Docker

```bash
docker compose up -d --build
```

Бот настроится на ежедневный запуск в **9:00** (или во время из `POST_HOUR`/`POST_MINUTE`).
Планировщик (`scheduler.py`) держит контейнер живым и запускает `main.py` в заданное время.
Контейнер работает от непривилегированного пользователя, с read-only корневой файловой
системой, без Linux capabilities и с writable volumes только для `/app/logs`, `/app/state`
и временной директории `/tmp`. Входящие порты не публикуются.

Проверить конфигурацию и healthcheck:

```bash
docker compose config
docker compose ps
docker inspect --format '{{.State.Health.Status}}' cyan-day
```

Healthcheck ожидает `healthy` после стартовой задержки. При остановке Compose даёт
планировщику до 30 секунд на корректное завершение; JSON-логи ограничены 10 MiB на файл,
максимум тремя файлами. Именованные `cyan-day` и `cyan-day-isolated` удобны для одной
установки, но могут конфликтовать при параллельных установках на одном Docker-хосте.

Сборка и compile smoke без публикации:

```bash
docker build -t cyan-day:local .
docker run --rm --entrypoint python cyan-day:local \
  -m compileall -q app main.py scheduler.py
```

> **Про сеть:** контейнер работает в отдельной Docker bridge-сети `cyan-day-isolated`.
> Она не подключается к сетям других Compose-проектов, входящие порты не публикуются,
> а контейнеру нужен только исходящий доступ к VK, Mistral и calend.ru. На сервере
> проверьте, что обычная Docker bridge-сеть выпускает исходящий трафик через NAT.
> Если сервер находится за CGNAT и bridge-NAT не работает, сначала исправьте сетевую
> конфигурацию Docker/провайдера, не подключая бота к host-сети.

Контейнер использует только именованные volumes `bot_logs` и `bot_state`, принадлежащие
этому Compose-проекту. Общие директории и volumes других проектов не монтируются.

Просмотр логов:

```bash
docker logs -f cyan-day
```

### Управление источниками

Встроенный SQLite-реестр содержит только code-defined адаптеры. Сейчас поддерживается тип `calendru_day` (также принимается алиас `calendru-day`). Новые источники сначала добавляются выключенными, затем проверяются и включаются:

```bash
docker compose run --rm bot python -m app.source_admin \
  --db /app/state/sources.sqlite3 add --name calendru \
  --type calendru_day --url 'https://calend.ru/day/{date}/'
docker compose run --rm bot python -m app.source_admin \
  --db /app/state/sources.sqlite3 test calendru
docker compose run --rm bot python -m app.source_admin \
  --db /app/state/sources.sqlite3 enable calendru
docker compose run --rm bot python -m app.source_admin \
  --db /app/state/sources.sqlite3 list --enabled
```

Для отката используйте `disable`; логическое удаление требует `remove --confirm`. Реестр хранится в volume `bot_state`. Дедупликация выполняется только в рамках одного запуска и не заменяет ledger публикаций: повторный запуск может снова опубликовать тот же праздник.

### Контентные слоты (cards-режим)

Альтернатива ежедневным праздникам — редакционные карточки с факт-чекингом. День делится на семь слотов: **утром — проверенные факты, днём — темы, вечером — мифы и разборы**. Каждая карточка имеет статус (`verified`/`unverified`/`disputed`/`refuted`/`rejected` → ФАКТ/МИФ/РАЗБОР), claims с provenance и теги. Режим включается переменной `CONTENT_MODE=cards` (по умолчанию `legacy`).

Сетка слотов:

| Слот | Время | Подходящие теги | Strict |
|---|---|---|---|
| `fact` | 09:00 | `status.verified` (проверенный факт) | да |
| `drink` | 10:30 | `drink.beer`, `drink.wine`, `drink.vodka`, `topic.production` | нет |
| `context` | 12:00 | `topic.context`, `topic.history`, `topic.people`, `topic.places` | нет |
| `custom_law` | 13:30 | `topic.customs`, `topic.law`, `topic.regulation` | нет |
| `trade` | 15:00 | `topic.trade`, `topic.production` | нет |
| `myth` | 17:00 | `format.myth`, `status.unverified`, `status.rejected` | да |
| `analysis` | 19:00 | `format.analysis`, `status.disputed`, `status.refuted` | да |

Strict-слоты не имеют запасного пула: если подходящих карточек нет, слот пропускается (в 09:00 не выйдет МИФ, в 17:00 не выйдет ФАКТ). Дневные слоты при пустом пуле берут любую свободную карточку.

Импорт карточки и план на дату:

```bash
docker compose run --rm bot python -m app.content_admin \
  --db /app/state/content.sqlite3 import --file card.json
docker compose run --rm bot python -m app.content_admin \
  --db /app/state/content.sqlite3 plan --date 2026-08-31
```

В образе лежит стартовый набор из ~30 карточек (`data/cards/`, собран из научных статей и музейных материалов с дословными цитатами). Импорт всего каталога — указать каталог вместо файла:

```bash
docker compose run --rm bot python -m app.content_admin \
  --db /app/state/content.sqlite3 import --file /app/data/cards
```

Особенности режима:

- **ФАКТ** (`verified`) публикуется дословно, без вызова Mistral — модель не может исказить факты.
- **МИФ/РАЗБОР** генерируются Mistral со строгой привязкой только к фактам карточки и обязательной маркировкой.
- **Догонка**: после простоя планировщик публикует просроченные слоты, но не больше `MAX_CATCHUP_SLOTS` постов за цикл опроса (остальные — в следующих циклах). Неудачные слоты перезапускаются, опубликованные повторно не отправляются (ledger с идемпотентностью).
- **Память карточек**: при `ALLOW_CARD_REUSE=false` планировщик избегает карточек, опубликованных за последние 7 дней.
- **Картинки**: при `WITH_PHOTOS=true` публикуется картинка из `image_url` карточки. Скачивание проходит те же SSRF-проверки (https, без редиректов и прокси, запрет приватных IP), но без allowlist хостов — URL задаёт редактор.
- **Тематические карточки на любой день**: `calendar_day: "00-00"` — карточка участвует в плане каждый день. Обычный формат `MM-DD` привязывает карточку к конкретной дате (праздники, юбилеи).

#### Уровни доверия источников

Каждый источник в `provenance` имеет `source_type` из закрытого словаря:

| `source_type` | Значение | Учитывается как доверенный |
|---|---|---|
| `academic` | научная статья, монография | да |
| `primary` | первичный документ (закон, архив) | да |
| `museum` | музейный материал | нет |
| `popular` | популярный сайт, СМИ | нет |
| `manual` | редакционная заметка (по умолчанию) | нет |

Карточка со статусом `verified` **обязана** иметь хотя бы один доверенный источник (`academic`/`primary`) — и при импорте, и при повышении статуса через `content_admin status`. Неизвестный `source_type` отклоняется. Остальные статусы могут опираться на любые источники.

#### Автотеги статуса

Тег `status.<статус>` (например, `status.verified`, `status.unverified`) добавляется к карточке автоматически при импорте и при смене статуса — именно по нему сетка слотов разделяет факты, непроверенное и мифы. Указывать `status.*` в JSON не нужно: совпадающий тег дедуплицируется, конфликтующий — ошибка импорта.

База карточек хранится в volume `bot_state` (`state/content.sqlite3` в контейнере).

## Известные ограничения

- **Картинки**: с токеном сообщества VK загрузка фото недоступна
  (`photos.getWallUploadServer`, `upload.photo_wall` → ошибка 27). Бот постит
  только текст (`WITH_PHOTOS=false`). Чтобы включить картинки — нужен
  **user-токен владельца группы** (см. ниже), после чего ставим `WITH_PHOTOS=true`.
- **Чтение стены**: `wall.get` / `wall.delete` тоже недоступны с токеном
  сообщества (ошибка 27). Проверять посты лучше в браузере
  (`vk.com/club<ID>`), а не через API.
- **User-токен**: с 2024 VK ограничил выдачу новых user-токенов через OAuth.
  Получение требует создания приложения и подтверждения. Инструкция — в
  разделе ниже.

### Как включить картинки (user-токен)

1. Создай standalone-приложение на `https://id.vk.com/about/business/go`.
2. Открой в браузере (под аккаунтом владельца группы):
   ```
   https://oauth.vk.com/authorize?client_id=<APP_ID>&display=page&redirect_uri=https://oauth.vk.com/blank.html&scope=offline,wall,photos,groups&response_type=token&v=5.199
   ```
3. Скопируй `access_token` из адресной строки.
4. Впиши в `.env` как `VK_TOKEN`, поставь `WITH_PHOTOS=true`.

## GitHub Actions

CI запускается на каждый push и pull request для `dev` и `main`, ежедневно в 06:00 UTC
и вручную через **Actions → CI → Run workflow**.

- **test** — pytest, compile smoke (`python -m compileall`) и Docker build.
- **smoke-mistral** — после `test` проверяет Mistral API только на scheduled/manual запусках,
  используя секрет `MISTRAL_API_KEY`.

GitHub Actions не запускает бота и не публикует в VK. Секрет не нужен для сборки и не должен
попадать в образ или командную строку. Cron задаётся в UTC и не переходит на летнее время
вместе с Москвой.

## Структура `.env`

| Переменная | Описание |
|---|---|
| `VK_TOKEN` | Токен сообщества VK |
| `VK_GROUP_ID` | ID группы (положительное число) |
| `MISTRAL_API_KEY` | Ключ Mistral |
| `POST_HOUR` / `POST_MINUTE` | Время ежедневного поста (по умолчанию 9:00) |
| `MISTRAL_MODEL` | Модель Mistral (по умолчанию `mistral-small-latest`) |
| `MAX_HOLIDAYS` | Сколько праздников публиковать в день (по умолчанию 3) |
| `WITH_PHOTOS` | Публиковать с картинками. `false` — только текст (работает с токеном сообщества). `true` — с картинками (нужен user-токен, иначе VK ошибка 27). В cards-режиме — картинка из `image_url` карточки |
| `CONTENT_MODE` | `legacy` (праздники) или `cards` (редакционные карточки, 7 слотов в день) |
| `CONTENT_DB` | Путь к SQLite карточек (по умолчанию `state/content.sqlite3`) |
| `SLOT_TIMES` | Семь времён слотов через запятую, `HH:MM` (по умолчанию 09:00…19:00) |
| `BOT_TIMEZONE` | Часовой пояс даты постов (по умолчанию `Europe/Moscow`) |
| `MAX_CATCHUP_SLOTS` | Максимум публикаций просроченных слотов за цикл догонки (по умолчанию 7) |
| `ALLOW_CARD_REUSE` | `true` — повторять недавно опубликованные карточки; `false` — избегать карточек за последние 7 дней |
| `LOG_LEVEL` | Уровень логирования |

Скопируйте `.env.example`; реальные секреты храните только в `.env`. Основные числовые
и временные параметры проверяются при старте. `SLOT_TIMES` должен содержать ровно семь
значений `HH:MM`, а `VK_GROUP_ID` — положительное число без префикса `club`.
