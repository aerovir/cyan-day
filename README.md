# 🥂 «Синий день календаря»

«Синий день календаря» каждый день заглядывает в календарь и находит там праздники, о которых человечество почему-то предпочитало молчать. День космонавтики, День объятий с кактусом или Международный день ирландского кофе — любой повод становится достойной причиной ненадолго забыть о здравом смысле. Каждый праздник превращается в ироничную историю о жизни, работе, внезапной мудрости и других последствиях слишком серьёзного отношения к реальности. Ведь если уж день официально признан праздничным, значит, его необходимо отметить — желательно с юмором, лёгким похмельем и верой в светлое будущее.

Бот публикует в VK-группе шесть постов в день по карточному расписанию: 12:00, 14:00, 16:00, 18:00, 20:00 и 22:00 в фиксированном UTC+2. В слот напитков Gemini генерирует коктейльный рецепт — классический или шуточный; остальные слоты используют редакционные карточки.


## Как это работает

```
SQLite SourceRegistry (включённые кодо-определённые адаптеры)
        │  SourceItem: название, описание, картинка
        ▼
Дедупликация событий → ИИ Gemini (иронично-алкогольный стиль)
        │
        ▼
VK API (публикует посты)

При пустом/отсутствующем реестре режим auto сохраняет fallback на calend.ru.

calend.ru (праздники на сегодня)
        │  (legacy fallback)
        ▼
ИИ Gemini (переписывает описание в иронично-алкогольном стиле)
        │  (пост)
        ▼
VK API (публикует пост с картинкой в группу)
```

## Архитектура

| Модуль | Назначение |
|---|---|
| `app/holidays_parser.py` | Сбор праздников с calend.ru |
| `app/ai_generator.py` | Генерация ироничных алкогольных постов через Gemini |
| `app/vk_publisher.py` | Публикация постов в VK-группу |
| `app/main.py` | Оркестратор: собрать → сгенерировать → опубликовать |
| `app/content_store.py` | SQLite: карточки, claims/provenance, план и ledger публикаций |

## Запуск

### 1. Получить ключи

#### VK (токен группы)
1. Создай сообщество (группу) VK.
2. Зайди в **Управление → Настройки → Работа с API**.
3. Создай **токен сообщества** с правами: `wall`, `groups`, `photos`.
4. Скопируй токен — пригодится как `VK_TOKEN`.
5. ID группы (число) — как `VK_GROUP_ID`.

#### Gemini (API-ключ)
1. Открой [Google AI Studio](https://aistudio.google.com) и выбери проект.
2. Создай Gemini API key и скопируй его; храни ключ в секрете.
3. Для генерации используется `GEMINI_MODEL` (по умолчанию `gemini-3.5-flash-lite`). Доступные модели и квоты зависят от проекта и могут меняться.
4. Для Gemini Developer API нужны `GEMINI_API_KEY` и `GEMINI_MODEL`; имя/номер проекта отдельно в запросе не используются.

### 2. Настроить `.env`

Скопируй пример и заполни локально:

```bash
cp .env.example .env
# отредактируй: VK_TOKEN, VK_GROUP_ID, GEMINI_API_KEY
```

Укажи ключ только в `GEMINI_API_KEY=` и модель в `GEMINI_MODEL=`. `VK_TOKEN` и `VK_GROUP_ID` — отдельные настройки публикации VK.

> **Важно:** `.env` в `.gitignore` — ключ не попадёт в репозиторий.

### Генерация изображений

`IMAGE_PROVIDER` принимает `none`, `pollinations` или `cloudflare`. Pollinations использует анонимный image endpoint; Cloudflare — Workers AI и требует Account ID/API Token. Источник изображения выбирается в следующем порядке:

1. `image_url` у события или редакционной карточки (изображение источника имеет приоритет);
2. изображение, сгенерированное выбранным провайдером (`pollinations` или `cloudflare`), если исходной картинки нет;
3. текстовый пост без картинки, если генерация отключена или завершилась ошибкой и
   `IMAGE_FALLBACK_TO_TEXT=true`.

Пример настройки:

```dotenv
WITH_PHOTOS=true
IMAGE_PROVIDER=pollinations
IMAGE_BASE_URL=https://image.pollinations.ai/prompt
IMAGE_MODEL=flux
IMAGE_TIMEOUT_SECONDS=30
IMAGE_FALLBACK_TO_TEXT=true
```

`IMAGE_BASE_URL` — базовый URL совместимого image endpoint, а `IMAGE_MODEL` — имя модели,
передаваемое провайдеру. `IMAGE_TIMEOUT_SECONDS` ограничивает ожидание ответа; значение
`IMAGE_FALLBACK_TO_TEXT=true` не блокирует публикацию, если сервис изображений недоступен.

Анонимный endpoint Pollinations не требует API-ключа, но его доступность, скорость и
лимиты не гарантируются: возможны rate limit, временные ошибки и изменения политики
сервиса. Перед отправкой запроса промпт уходит во внешний сервис Pollinations. Не включайте
в текст праздника, карточки или промпт секреты, персональные данные и другую информацию,
которую нельзя передавать третьей стороне.

#### Cloudflare Workers AI

Для генерации через Cloudflare установи `IMAGE_PROVIDER=cloudflare` и заполни `CLOUDFLARE_ACCOUNT_ID` и `CLOUDFLARE_API_TOKEN` в `.env`. Токен должен иметь доступ к Workers AI; не коммить его и не передавать в командной строке. По умолчанию используется `@cf/black-forest-labs/flux-1-schnell`. В тесте Cloudflare отклонил поля `width`/`height` для этой модели, поэтому размер выдачи определяется самой моделью; запрос без них вернул JPEG 1024×1024. При ошибке сохранится текстовый fallback, если `IMAGE_FALLBACK_TO_TEXT=true`.

Отдельная генерация без публикации в VK:

```bash
mkdir -p output
docker compose --profile images run --rm --no-deps image-admin generate \
  --provider cloudflare \\
  --prompt "archival satirical editorial illustration of a historic tavern" \\
  --output cloudflare-test.jpg
```

`image-admin` передаёт контейнеру только настройки изображений; VK и Gemini credentials для этой команды не нужны. Сгенерированные файлы сохраняются в `output/`.

Параметры image provider задаются в `.env`; GitHub Actions не запускает бота и не публикует посты.

### 3. Запуск через Docker

```bash
docker compose up -d --build
```

В `cards`-режиме планировщик ежедневно обрабатывает слоты из `SLOT_TIMES` — по умолчанию 12:00, 14:00, 16:00, 18:00, 20:00 и 22:00 в фиксированном UTC+2. `POST_HOUR`/`POST_MINUTE` применяются только в `legacy`-режиме. Пропущенные слоты старше `SLOT_GRACE_SECONDS` не публикуются задним числом.
Планировщик (`scheduler.py`) держит контейнер живым, строит ежедневный план и передаёт наступивший слот оркестратору.
Контейнер работает от непривилегированного пользователя, с read-only корневой файловой
системой, без Linux capabilities и с writable volumes только для `/app/logs`, `/app/state`
и временной директории `/tmp`. Входящие порты не публикуются.

Проверить конфигурацию и healthcheck:

```bash
docker compose config
docker compose ps
docker inspect --format '{{.State.Health.Status}}' cyan-day
```

Healthcheck ожидает `healthy` после стартовой задержки. При остановке Compose даёт
планировщику до 30 секунд на корректное завершение; JSON-логи ограничены 10 MiB на файл,
максимум тремя файлами. Именованные `cyan-day` и `cyan-day-isolated` удобны для одной
установки, но могут конфликтовать при параллельных установках на одном Docker-хосте.

Сборка и compile smoke без публикации:

```bash
docker build -t cyan-day:local .
docker run --rm --entrypoint python cyan-day:local \
  -m compileall -q app main.py scheduler.py
```

> **Про сеть:** контейнер работает в отдельной Docker bridge-сети `cyan-day-isolated`.
> Она не подключается к сетям других Compose-проектов, входящие порты не публикуются,
> а контейнеру нужен только исходящий доступ к VK, Gemini API и calend.ru. На сервере
> проверьте, что обычная Docker bridge-сеть выпускает исходящий трафик через NAT.
> Если сервер находится за CGNAT и bridge-NAT не работает, сначала исправьте сетевую
> конфигурацию Docker/провайдера, не подключая бота к host-сети.

Контейнер использует только именованные volumes `bot_logs` и `bot_state`, принадлежащие
этому Compose-проекту. Общие директории и volumes других проектов не монтируются.

Просмотр логов:

```bash
docker logs -f cyan-day
```

### Управление источниками

Встроенный SQLite-реестр содержит только code-defined адаптеры. Сейчас поддерживается тип `calendru_day` (также принимается алиас `calendru-day`). Новые источники сначала добавляются выключенными, затем проверяются и включаются:

```bash
docker compose run --rm bot python -m app.source_admin \
  --db /app/state/sources.sqlite3 add --name calendru \
  --type calendru_day --url 'https://calend.ru/day/{date}/'
docker compose run --rm bot python -m app.source_admin \
  --db /app/state/sources.sqlite3 test calendru
docker compose run --rm bot python -m app.source_admin \
  --db /app/state/sources.sqlite3 enable calendru
docker compose run --rm bot python -m app.source_admin \
  --db /app/state/sources.sqlite3 list --enabled
```

Для отката используйте `disable`; логическое удаление требует `remove --confirm`. Реестр хранится в volume `bot_state`. Дедупликация выполняется только в рамках одного запуска и не заменяет ledger публикаций: повторный запуск может снова опубликовать тот же праздник.

### Контентные слоты (cards-режим)

Карточный режим публикует шесть слотов в фиксированном часовом поясе UTC+2 (`Etc/GMT-2`, без сезонного перевода). Статусы карточек (`verified`/`unverified`/`disputed`/`refuted`/`rejected`) дают метки ФАКТ/МИФ/РАЗБОР; карточки также содержат claims, источники и контролируемые теги.

Сетка слотов:

| Слот | Время | Содержание |
|---|---:|---|
| `fact` | 12:00 | проверенная карточка (`status.verified`) |
| `drink` | 14:00 | рецепт коктейля, сгенерированный Gemini |
| `context` | 16:00 | контекст, история, люди, места, торговля и производство |
| `custom_law` | 18:00 | обычаи и законы |
| `myth` | 20:00 | карточка о мифе или неподтверждённом утверждении |
| `analysis` | 22:00 | разбор спорной темы |

Торговые карточки (`topic.trade`, `topic.production`) объединены со слотом `context`. Карточный план старается заполнить шесть слотов уникальными карточками; при недостатке подходящего типа использует доступную карточку, но сохраняет её реальную метку. Если контента вообще недостаточно или API недоступен, соответствующая публикация может быть пропущена.

Слот `drink` чередует типы рецепта случайным образом при создании плана на дату; выбранный режим сохраняется при повторном запуске. Шуточный промпт просит заменить один-два ингредиента аналогами и сохранять меры/пропорции; классический — дать известную стандартную рецептуру без замен. Gemini не сверяется с внешним источником, поэтому «классичность» не является независимой факт-проверкой. В опубликованной строке рецепта меры форматируются из проверенной приложением структуры.

К карточным и recipe-постам приложение добавляет отдельную строку хештегов под текстом: кодовый тег `topic.history` становится `#topic_history`; recipe-посты получают `#drink_cocktail`, `#format_recipe` и типовой тег `#tone_ironic` либо `#tone_classic`.

При рестарте просроченные слоты не выпускаются пачкой: обрабатывается только последний слот, наступивший в пределах `SLOT_GRACE_SECONDS`; более старые пропускаются. Карточный режим задаётся `CONTENT_MODE=cards`.

Импорт карточки и план на дату:

```bash
docker compose run --rm bot python -m app.content_admin \
  --db /app/state/content.sqlite3 import --file card.json
docker compose run --rm bot python -m app.content_admin \
  --db /app/state/content.sqlite3 plan --date 2026-08-31
```

В образе лежит стартовый набор из ~30 карточек (`data/cards/`, собран из научных статей и музейных материалов с дословными цитатами). Импорт всего каталога — указать каталог вместо файла:

```bash
docker compose run --rm bot python -m app.content_admin \
  --db /app/state/content.sqlite3 import --file /app/data/cards
```

Особенности режима:

- **ФАКТ** (`verified`) публикуется дословно, без вызова Gemini — модель не может исказить факты.
- **МИФ/РАЗБОР** генерируются Gemini со строгой привязкой только к фактам карточки и обязательной маркировкой.
- **Просроченные слоты**: после простоя старые слоты не публикуются пачкой. Последний наступивший слот можно выполнить только в пределах `SLOT_GRACE_SECONDS`; более старые пропускаются. Неудачные попытки обрабатываются через ledger, а опубликованные и `unknown`-слоты не отправляются повторно без сверки.
- **Память карточек**: при `ALLOW_CARD_REUSE=false` планировщик избегает карточек, опубликованных за последние 7 дней.
- **Картинки**: при `WITH_PHOTOS=true` публикуется картинка из `image_url` карточки. Скачивание проходит те же SSRF-проверки (https, без редиректов и прокси, запрет приватных IP), но без allowlist хостов — URL задаёт редактор.
- **Тематические карточки на любой день**: `calendar_day: "00-00"` — карточка участвует в плане каждый день. Обычный формат `MM-DD` привязывает карточку к конкретной дате (праздники, юбилеи).

#### Уровни доверия источников

Каждый источник в `provenance` имеет `source_type` из закрытого словаря:

| `source_type` | Значение | Учитывается как доверенный |
|---|---|---|
| `academic` | научная статья, монография | да |
| `primary` | первичный документ (закон, архив) | да |
| `museum` | музейный материал | нет |
| `popular` | популярный сайт, СМИ | нет |
| `manual` | редакционная заметка (по умолчанию) | нет |

Карточка со статусом `verified` **обязана** иметь хотя бы один доверенный источник (`academic`/`primary`) — и при импорте, и при повышении статуса через `content_admin status`. Неизвестный `source_type` отклоняется. Остальные статусы могут опираться на любые источники.

#### Автотеги статуса

Тег `status.<статус>` (например, `status.verified`, `status.unverified`) добавляется к карточке автоматически при импорте и при смене статуса — именно по нему сетка слотов разделяет факты, непроверенное и мифы. Указывать `status.*` в JSON не нужно: совпадающий тег дедуплицируется, конфликтующий — ошибка импорта.

База карточек хранится в volume `bot_state` (`state/content.sqlite3` в контейнере).

## Известные ограничения

- **Картинки в VK**: с токеном сообщества VK загрузка фото недоступна
  (`photos.getWallUploadServer`, `upload.photo_wall` → ошибка 27). Поэтому даже при
  сгенерированной или исходной картинке бот с `VK_TOKEN` сообщества может опубликовать
  только текст. Для фактической загрузки картинок нужен **user-токен владельца группы**
  (см. ниже), после чего ставим `WITH_PHOTOS=true`.
- **Чтение стены**: `wall.get` / `wall.delete` тоже недоступны с токеном
  сообщества (ошибка 27). Проверять посты лучше в браузере
  (`vk.com/club<ID>`), а не через API.
- **User-токен**: с 2024 VK ограничил выдачу новых user-токенов через OAuth.
  Получение требует создания приложения и подтверждения. Инструкция — в
  разделе ниже.

### Ручная генерация изображения через Docker

Команда запускает только запрос к Pollinations и сохраняет результат в `./output`; scheduler и VK не запускаются, секреты VK/Gemini не нужны:

```bash
mkdir -p output
docker compose --profile images run --rm --no-deps image-admin generate \
  --prompt "archival satirical illustration of a historic Russian tavern" \
  --output tavern.jpg
```

Доступны `--model`, `--timeout`, `--force` и `--prompt-file`. Имя `--output` ограничено каталогом `/app/output`; существующий файл не перезаписывается без `--force`. Команда использует те же HTTPS/SSRF/MIME/10 MiB проверки, что и бот. Prompt передаётся внешнему сервису Pollinations и не должен содержать секреты или закрытые данные. Без API-ключа endpoint может быть ограничен rate limit или измениться.

### Как включить картинки (user-токен)

1. Создай standalone-приложение на `https://id.vk.com/about/business/go`.
2. Открой в браузере (под аккаунтом владельца группы):
   ```
   https://oauth.vk.com/authorize?client_id=<APP_ID>&display=page&redirect_uri=https://oauth.vk.com/blank.html&scope=offline,wall,photos,groups&response_type=token&v=5.199
   ```
3. Скопируй `access_token` из адресной строки.
4. Впиши в `.env` как `VK_TOKEN`, поставь `WITH_PHOTOS=true`.

## GitHub Actions

CI запускается на каждый push и pull request для `dev` и `main`, ежедневно в 06:00 UTC
и вручную через **Actions → CI → Run workflow**.

- **test** — pytest, compile smoke (`python -m compileall`) и Docker build.
- **smoke-gemini** — после `test` проверяет Gemini API только на scheduled/manual запусках,
  используя секрет `GEMINI_API_KEY`.

GitHub Actions не запускает бота и не публикует в VK. Секрет не нужен для сборки и не должен
попадать в образ или командную строку. Cron задаётся в UTC и не переходит на летнее время
вместе с Москвой.

## Структура `.env`

| Переменная | Описание |
|---|---|
| `VK_TOKEN` | Токен сообщества VK |
| `VK_GROUP_ID` | ID группы (положительное число) |
| `GEMINI_API_KEY` | Ключ Gemini |
| `GEMINI_MODEL` | Модель Gemini (по умолчанию `gemini-3.5-flash-lite`) |
| `CONTENT_MODE` | `cards` (шесть редакционных слотов, значение по умолчанию) или `legacy` (один запуск праздников) |
| `CONTENT_DB` | Путь к SQLite карточек (по умолчанию `state/content.sqlite3`) |
| `SLOT_TIMES` | Шесть времён через запятую, строго `12:00,14:00,16:00,18:00,20:00,22:00` |
| `BOT_TIMEZONE` | Часовой пояс планирования; `Etc/GMT-2` — фиксированный UTC+2 без DST |
| `SLOT_GRACE_SECONDS` | Допустимое опоздание для слота (по умолчанию `300` секунд); более старые слоты пропускаются |
| `POST_HOUR` / `POST_MINUTE` | Время запуска только в `legacy`-режиме (по умолчанию 9:00) |
| `MAX_HOLIDAYS` | Лимит праздников в `legacy`-режиме (по умолчанию 3) |
| `WITH_PHOTOS` | Разрешить публикацию картинок. `false` — только текст; `true` — использовать исходную или сгенерированную картинку (для загрузки в VK нужен user-токен, иначе ошибка 27) |
| `IMAGE_PROVIDER` | `none`, `pollinations` или `cloudflare` (по умолчанию `none`) |
| `IMAGE_BASE_URL` / `IMAGE_MODEL` / `IMAGE_TIMEOUT_SECONDS` | Настройки Pollinations |
| `CLOUDFLARE_ACCOUNT_ID` | Account ID Cloudflare (нужен только при `IMAGE_PROVIDER=cloudflare`) |
| `CLOUDFLARE_API_TOKEN` | API Token Cloudflare с правом Workers AI; хранить только в `.env` |
| `CLOUDFLARE_IMAGE_MODEL` | Workers AI model ID (по умолчанию `@cf/black-forest-labs/flux-1-schnell`) |
| `CLOUDFLARE_IMAGE_TIMEOUT_SECONDS` | Таймаут Workers AI (по умолчанию `60`) |
| `IMAGE_FALLBACK_TO_TEXT` | При ошибке генерации продолжить публикацию без изображения (по умолчанию `true`) |
| `ALLOW_CARD_REUSE` | `true` — повторять недавно опубликованные карточки; `false` — избегать карточек за последние 7 дней |
| `LOG_LEVEL` | Уровень логирования |

Скопируйте `.env.example`; реальные секреты храните только в `.env`. Числовые
и временные параметры проверяются при старте. `SLOT_TIMES` должен содержать ровно шесть
уникальных времён в заданном порядке, а `VK_GROUP_ID` — положительное число без префикса `club`.
